# 提案：插件生命周期与分发形态（官方插件手动安装）

Status: proposed

## Problem

插件系统生命周期五段缺三：分发（无）、安装（无主动管道）、升级（未定）。插件 v1 的 seeder
「缺则种」让官方件默认自动装，且曾衍生出「官方件不可卸载」的错误执行（见
implemented/product/2026-11-10-seed-uninstallable）。用户 2026-11-10 连续三轮裁定，把插件
获取形态彻底定死。

## Decision（用户 2026-11-10 裁定）

- **官方插件 = 手动安装**。首发自动补齐机制**整体废除**（第一轮裁「可卸载」、第二轮裁
  「术语退役」、本轮裁「机制本身废除」）：安装包不再携带插件，新装机零插件。
- **分发 = GitHub Release**（项目无托管插件的服务器）。
- **安装 = 本地 zip 导入，唯一管道**。完整性 = manifest 校验 + zip 结构与路径围栏；
  第三方插件走同一管道（契约只认形状不认出身），自担风险；信任模型官方独占不变
  （不防恶意只防误用，明示写进契约文档）。
- **更新检查 = 不做**。升级 = 从 GitHub Release 重新下载 zip 重新导入，同一管道做版本比较
  （同版本拒、低版本拒并提示）。
- **词汇退役**：「种子件」→ 官方随附概念不复存在；「opt-out」→ 已卸载清单随机制一起删除。

## Consequences

- 新装机零插件：「問」（AI 共读）不再开箱即用——首启体验变化，README 与发版说明须明示
  「插件请到 GitHub Release 下载后安装」。
- `PluginManager` 简化：删 provision / bundledDirs / 已卸载清单 / `bundled` 标记；
  `uninstall` 删记录写入（无复活问题）；设置页删「官方隨附」标注。
- 打包瘦身：`extraResources` 移除 `plugins/`；`client/plugins/` 保留为**开发工作区**
  （時鐘/問 源码 + 开发验证）。
- 依赖：zip 解析需声明 `fflate`（MIT，AGPL 兼容，已在依赖树；动工时先征得同意再落声明）。
- ⚠ **开发侧加载方式未定**（不进产品路径）：dev 环境怎么把工作区插件装进测试实例——
  候选 = dev-only 环境变量触发补齐 / 开发时手动 zip 导入。待用户定，未定前不实现。

## Alternatives considered

- **随包 + 「恢復官方隨附」一键重装**：输在——仍是一种自动/半自动获取，违背「手动安装」
  的明示裁定；且资源包体积只为提「重装便利」，与 GitHub Release 分发重复。
- **自动补齐 + 已卸载清单豁免**（上一版设计）：输在——用户三轮裁定层层收紧（可卸→退役
  术语→废机制），保留任何形态的自动获取都是没听懂。

## Acceptance criteria（实现批的验收）

1. `plugins:install-zip` 管道：对话框收在主进程（渲染层零路径）、manifest + zip 双校验、
   路径围栏、版本比较（同/低版本拒）、临时目录原子落位；
2. 设置页「安裝插件…」入口 + 安装后全量重载；错误可见不静默；
3. provision / 已卸载清单 / bundled 标记全链删除（含 IPC、runtime、设置页、测试）；
4. 打包配方移除 extraResources 的 plugins；BUILD.md 同步；
5. 单测覆盖：zip 根形态/单文件夹形态/坏 zip/路径穿越/多顶层目录/版本比较/卸载后重装；
6. 契约文档补第三方立场明示 + zip 打包规范；面向人的插件开发指南另立（与「人类可读文档」
   TODO 同源）。

## Risks

- 「問」从开箱即用变为需手动获取——新用户可能不知道有这个功能。缓解：README 安装节 +
  设置页插件组空态文案给「插件是什么、去哪装」的人话指引（形态随实现批定）。
