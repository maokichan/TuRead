# 决策：书内链接的交互形态 = 跳转到目标

Status: implemented

## Problem

Issue #2 修复（`attachLinkWatch`/`activateLink`，见 [`client/docs/KOOKIT.md`](../../../../client/docs/KOOKIT.md) §7）让书内链接点击
第一次有了行为，随之必须裁定**交互形态**：脚注类链接点击后是「跳转到注释位置」还是
「原地弹层展示注释内容」（Koodo Reader 的形态）。同时需要澄清概念边界——脚注/尾注/注释/
交叉引用/边注在渲染层是什么关系，「全量支持」指什么。

## Decision

- **统一术语 = 书内链接**（用户 2026-11-10 钦定）：命名**对象**不命名行为——弹层翻案也不改词；
  与**外部链接**成对，与代码 `link` 家族（`attachLinkWatch`/`activateLink`/`link-external`）1:1。
  候选淘汰：注释（撞批注）、锚链（「锚」归笔记锚定系统）、引用链接（「引用」归治理 +
  交叉引用只是子类）、跳转链接（行为命名，弹层下失效）、维持脚注（编排词指代不全）。
  脚注/尾注/注释/边注此后只作书籍编排讨论用词。
- **形态 = 跳转**（用户 2026-11-09 裁定「总体可以接受」，弹层为可接受备选但不当选）：
  同章锚点原地滚动；跨章锚点跳章后定锚；锚点缺失落章首；死链接原地不动。
- **概念边界（渲染器口径）**：脚注/尾注/注释/交叉引用在 EPUB 机制层是**同一种东西**
  （`<a href>` → 锚点），区别只是书的编排位置，渲染器不区分也无法区分——「全量支持」
  的准确表述 = **书内内部链接机制全量支持**，上述四类自动覆盖。唯一有真实形态差异的是
  **边注**（页边注）：重排版没有「边」通道，EPUB 里本就降级为内联/链接，无专门支持、
  无条目立项。返回链接（`↩`）是同机制内部链接，往返闭环随之成立。
- **与用户批注（笔记 v3）的关系**：两个独立通道（书作者的注 vs 读者的批注），互不依赖，
  无合并条目；远期「AI 解析注释」只针对用户批注。
- **格式边界**：EPUB 全量（探针回归）；MOBI/AZW3 的 TOC 内链走同一通道（未实测），
  `kindle:` 脚注不跳（原地不动，不白屏）——显式半支持。

## Alternatives considered

- **弹层形态**（Koodo 式，点击原地浮窗展示注释内容）：输在——需要可靠的「这是脚注」判据
  （EPUB3 `epub:type="noteref"` 很多转制书不带，得靠文本启发式兜底，误判伤交叉引用）；
  新增浮层组件违反「文字即界面」的极简语汇；且遮挡正文与卡片页层次模型相抵。
  用户保留为可接受备选——若未来翻案，判据钩子 = `epub:type="noteref"` + kookit
  `isElementFootnote` 文本启发式（`[1]`/`注`/`※` 等，`navigationUtil.ts:250`）。
- **不处理**（维持浏览器默认导航）：即 Issue #2 本身，白屏病根，不成立。

## Consequences

- 所得：一次拦截覆盖全部注类编排；无新 UI 组件；往返闭环免费成立。
- 代价：读长注释（尾注整节）时离开原文位置，靠回跳链接/跳转历史回去——
  跳转历史（[TODO](../../../../TODO.md)「渲染与阅读器」组）的用户价值因此上升。
- 边界债：MOBI `kindle:` 脚注半支持是无条目挂账的显式边界（本笔记为账）；真要支持
  需逆向 kookit 的 `resolveHref`（foliate MOBI 侧），按需立项。
