# 决策：不建独立引导系统——逐个修交互，部件自带可发现性

Status: implemented

## Problem

用户观察实锤：真用户进入阅读界面后无人能主动呼出右欄卡片页——唯一的常驻召唤入口「卡」按钮静息墨色只随目录压印字 token 走（实际 10~14% 文字色，压印语汇），其余入口全是隐形加速器（反引号 / `p` / `c` / 命令面板，对不知道其存在的人等于不存在）。全应用也没有通知、帮助、首次引导类设施。评估由此提出问题：要不要建一套独立引导系统（首启动流程 / 教练标记 / 帮助中心）来兜住可发现性。

## Decision

用户定：**不建独立引导系统，逐个修交互**。

- 「优秀的交互不需要多余引导」这条既有纪律的本意 = **防 AI-slop 话术填满设计版面**，不是拒绝可见性工程——把可见路径修到自解释（快捷键只当加速器，无人必须知道键位）是正当修法。
- 判据：问题清单短（当前实锤仅「卡」按钮一处，用户自评"只有这一个比较严重的问题"）；引导内容随功能迭代腐烂（每个部件改动都要同步维护引导，常驻税）；引导系统本身即 chrome，与零控件沉浸相抵。
- 现有设置页键位只读清单（批1.22）即唯一引导材料，不新建设施。
- 首落点 = 「卡」按钮静息浓度按主题校准（专用档 `--card-corner-ink`，浅 20% / 深 26% 起步，真机四主题定稿）；可选灯的法则延伸（接近显影）；不引入提示文案与首次演示。
- 再议触发 = 出现第二个同类严重问题。

## Alternatives considered

- **独立引导系统**（首启动 onboarding / 教练标记 / 帮助中心）：输在——应用核心概念仅五个（导入 / 打开 / 读 / 选中笔记 / 设置），概念数撑不起一套系统；引导内容是常驻税，随功能迭代必然过时腐化；与防 slop 纪律直接冲突（引导面正是话术容易堆积的地方）。

## Consequences

换来的：修复聚焦部件本身——可发现性是部件属性，不是系统服务；无常驻引导内容要维护；「待真机复看」类验收随做随销。付出的：每个新部件必须自带可发现性，没有系统兜底；部件的静息可见度成为设计评审的必查项（浓度档位与「压印字 = 隐没」的默认语汇之间，为可发现性让步要有显式理由）。
