# 决策：笔记区 v3——三层数据模型（锚/笔记/文档）与编辑器特性支持

Status: implemented

## Problem

笔记域四个结构性缺口：① 锚点只有内容流一族（Norm+Fragment），PDF/扫描版无法标注
（`getSelectionAnchor` 对 PDF 恒 null，"第二批"久未排期）；② body 纯文本，承载不了结构化
表达，与 Obsidian 零流通；③ 模型无「样式」维度——kookit 引擎原生支持背景/下划线/波浪/删除线
四种，我们只有四色底纹；④ 笔记是原子，变不成「作品」——没有以文档形式管理、生产的层。
前置裁定：本轮**不碰插件系统**——动的是宿主页面（筆記页/右键/命令面板），不是贡献点挂载
机制；接缝仅「問」读笔记数据（挂起的插件内容专题）与贡献点扩展（远期）。

## Decision（已落地：批N1–N5，git 为准）

**三层，各自独立演进（下为裁决；实现细则随代码与各 feature 页）：**

1. **锚点层 = 承载体制二分**
   - 内容流锚（现行 Norm+Fragment）不动，文字类载体用；
   - **几何页锚**（新增）：`{页码, shape, 坐标, 旋转?}`，位图载体（PDF/扫描版）专用。
     shape 两态：**rect 框选**（图片/公式/表格）+ **stroke 记号笔**（自由 polyline、点列抽稀
     ——歪斜文字/手写体用）；坐标用引擎原生空间（kookit PDF = pdf 用户空间点，缩放无关，
     回显经 viewport 换算——第一批文字选区已按此落地）。
   - **OCR 不进渲染管线**：引擎重（几十 MB）、错字层污染检索与锚点、生态已有预处理标准解
     （OCRmyPDF 类产隐藏文本层，kookit 直接受益）。文本能力（excerpt/检索/AI 上下文）在书带
     文本层时可用，否则诚实降级；将来若做 = 导入期可选预处理产 sidecar（与既有 PP-OCRv5
     路线同引擎不同用途）。

2. **笔记层 = body 原生 Markdown + 色样正交**
   - body → 原生 Markdown（Markdown 对纯文本透明，旧内容原样可读）；`excerpt` 仍是锚点
     证据，不掺和内容；
   - `markStyle`：四样（底纹/下划/波浪/删除）× 四色，正交两维；右键菜单两级（先样后色）；
   - kind 收敛一并落（`'note'` 退役，呈现只按 body 有无）；写透补偿口径（P2）顺手定；
   - schema 大改不保旧版兼容（用户拍板「不担心」）——v3→v4 只做最简数据搬运，不为兼容扭曲
     设计；迁移器退役评估随批。

3. **文档层 = vault 真文件 + 内置编辑器**
   - 定位红线：**不取代 Obsidian**——笔记区 = 建立在阅读之上的生产管道（消费内容 → 生产
     笔记 → 生产文档）；支持导出、在 Obsidian 中打开、Obsidian 侧联动插件（远期立项）；
   - vault = 真实 .md 文件目录（默认 userData 下，允许指向任意文件夹，含用户的 Obsidian 库）；
   - 两类文件：**汇编文档**（用户所有，wikilink 引用笔记 `![[note-<id>]]`）+ **笔记档案**
     （生成物，每书一份、可重生成覆盖，节标题 = `note-<id>`，内含 excerpt+body+色样元数据）
     ——档案使引用在 Obsidian **可解析、可反链**；我们这边解引用成活笔记卡（可点跳回原文）；
   - 编辑器：源码 + 预览 + **所见即所得**（用户裁定 WYSIWYG 纯增益，进范围）；实现顺序
     源码+预览在前，WYSIWYG 随后，同一交付线。
   - **归属（用户 2026-11-07 裁定）**：文档视图住**筆记区**（「筆」工具栏切入），不设独立
     侧栏项——文档 = 消费笔记所生产的内容，离开笔记的文档区没有意义。

### 编辑器特性支持矩阵（本笔记的点名内容）

| 面 | v1 支持 | v1 明确不做 |
|---|---|---|
| 笔记 body（输入栏/卡片） | OFM 小子集：粗斜体/列表/引用/行内代码/链接 | mermaid、`%%注释%%` 等长尾（挂清单，用到再加） |
| 文档层（编辑器/预览） | OFM 核心：wikilink / embed / callout / tag / frontmatter / 基础 GFM；数学公式可选 | 同上；库管理/同步/发布等 Obsidian 核心域 |
| 编辑形态 | 源码 / 预览 / 所见即所得 三态 | — |

## Alternatives considered

- **OCR 进渲染管线**：输在——重、错字层污染检索/锚点/下游、重复生态已解的问题；降级为
  导入期可选增益。
- **文档层存库表（新表管理 md）**：输在——失去「Obsidian 直接打开文件夹」的物质基础；
  真文件是双向流通的前提，不是实现细节。
- **WYSIWYG 不做（初版提案）**：被用户推翻——交互便利、纯增益。
- **几何锚照旧后置**：输在——schema 反正要动，锚点族一次到位比二次迁移便宜；扫描版笔记
  从「永远做不了」变「本轮交付」。
- **引用语法自创（`note://` 类 URI）**：输在——Obsidian 不识别，流通即破裂；wikilink 是
  方言共识。

## Consequences

**换来的**：扫描版 PDF（无文本层）有了标注入口（几何页锚两态：框选走 kookit 现成路径、
记号笔自绘 SVG 层）；body 原生 Markdown + 色样正交（4 样 × 4 色，`--mark-line-*` 描边族）；
vault 真文件 = Obsidian 反链的物质基础；编辑器三态（源码 = 唯一真相，所见即所得是它的视图）。
**付出的**：坐标换算依赖 kookit 内部（`chapterDocList`/`getPdfScale`，升级敏感面已入
`KOOKIT.md` §9）；档案 vs 手改的一致性靠「生成物勿手改 + 整体覆盖」口径；文档层体量
按矩阵收口（「不取代 Obsidian」是红线）。**待真机复看**：几何拖曳手感与落点精度、
四样在 EPUB/PDF 的观感、Obsidian 反链实效——探针证不了交互手感。
