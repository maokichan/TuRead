# 产品方向（研读仪器）

> 本文件记**产品级方向陈述**（用户定）：它们是后续批次的先验；条款改动 = 方向改动，须用户明示。
> 现状与交接看 [`STATUS.md`](STATUS.md)，视觉基线看 [`../client/docs/STYLE.md`](../client/docs/STYLE.md)——
> 本文只立"往哪去"，不承载实施细节。

## 1. 强交互研读（模型驱动的阅读假设）

研读型阅读从来强交互（查证、理脉、对照多源）；这不是新需求，新的是**成本曲线**：模型让工具走向文本
（带着阅读位置上下文就地干活），并把提取工作接过去（人从抄写员变成策展人）。摩擦降一个量级，
交互频率变一个量级——偶发查证变成连续的对话式研读。判据：

- 工具是**客人**：零延迟召唤、零残留退场；产出落进**用户拥有的结构**（笔记库、用户画的图），不是聊天日志。
- 模型驱动 ≠ 聊天优先：**预计算的上下文**（如"本章提到的人名，已抽好，悬停即现"）优于对话入口；聊天是未预料问题的兜底。
- 一切产出必须能**锚回原文**——定位系统的锚点级溯源是竞品没有的护城河，强交互做得越深它越深。

## 2. 卡片层次化（界面的空间语法）

阅读界面 = **浮在书库之上的卡片层**；不是弹窗，也不是全屏沉浸窗。层级由空间本身声明：
下层保持存活、侧边栏常亮「書」——"阅读器和书库层的关系"由布局回答，不靠返回按钮解释。

- 进出动效隐喻：阅读卡**从被点封面的位置长大**（transform-origin 锚在封面矩形上），退场反向、更快。
- 阅读卡**零自带 chrome**：书名声明进窗口标题栏（原"搜索本書內容"占位随之退役）。
- 沉浸态哲学演进：从"一个全屏状态"变为**卡片自身的纪律**（零控件约束移交给卡片）；
  STYLE §5.8 将随批 1.5 重立；F11 语义（原 = 进入全屏）届时重定。
- 该模型同时是 §1 的基底：阅读卡是锚面，地图/白板/对照的另一本书都是同一套空间语法里的层。

## 3. 端形态（桌面 = 书房）

竖屏设备的优势在**线性消费**（身位：躺着/通勤读；栏宽：竖屏宽度天然落在理想行长）；
桌面的优势在**画布**（地图、关系图、多书对照、键盘、精确指针、多面板）。两种阅读的物理规律不同：

- **TuRead 不与手机抢床边那本书，赌的是书桌前那两小时。** 桌面端 = 研读仪器（本方向的主场）；
  线性消遣让给竖屏设备，不追。
- 远期跨端形态 = **竖屏轻读端 + 桌面研读端共一份数据**，各干各的活；不是把桌面端缩小。
- **挂载线的定位**：它是研读模式的核心机构（正文零控件 + 工具恒定可达），不是横屏遗留。
  卡片模型中它进化为"卡片边缘即挂载线"（工具层挂在卡的边上）；竖屏跨端时线可转世
  （底边线、面板自下升起——移动端抽屉本是其近亲），届时另议。
