# TuRead 需求讨论纪要（2026-09-09）

这次讨论的需求整理如下。

划线标记与笔记是莉莉丝的核心需求，定位高优，支持弹窗和旁注两种注释形态；底层契约其实已经立好（笔记、划线、定位系统三原语都已预留接口），排期路径就是先把笔记的数据形状定下来，再走 UI 选段、存储，同步可以后置。书库收纳和分类这边，秋山澪说的"左目录右书"我们理解为书库/书架的整体布局而非阅读器内部布局，所以综合下来的方案是目录树线性展开——书库左侧用一棵目录树逐级展开来管理；这里有个关键定界：分类法（中图法或自定义）只是可自定义的规则，决定书怎么归类，它不定义容器，真正要定义的是容器这个实体，也就是书单/书库（Collection），它装的是若干书籍的索引而不是文件拷贝，可以递归包含子书单从而构成树状索引，另外再配一个简易的 tag 系统做正交索引，索引容器和本地文件夹的冲突（书是引用不是拷贝）后续再解决。显示层面新增第三种视图，把封面抽象成主色色块来降噪，看原图直接复用右侧详情抽屉，视图切换做成状态栏按钮的三态循环（列表→网格→色块），主色从封面缩略图取，主题色和色相的冲突问题不大，这条定了。

关于跳转历史，行动树的想法我们评估后决定驳回，因为注释和跳转虽然会打断线性阅读，但人的体验归根结底是线性的，所以改用状态机做前进/后退栈（undo/redo），随笔记落地后实施。另外键鼠操作要提为高优，现在单击详情、双击打开、Enter/Space/Delete 这些语义都是散落的特例，后面色块视图、房间、阅读器会有更多意图打架，所以引入意图层加键鼠绑定表，一键只归属一个意图、冲突显式裁决，范围从书库域先行，再扩到阅读器和房间。

远期确认要做的是 TTS 有声阅读和 AI 解析注释，都定位成官方插件形态，前置条件是插件系统完善、笔记落地之后再做。多主题并存（群里提到的渐变）还在讨论中，模型未定，因为现在产品是单主题切换。
