# ops/ —— 仓库治理（agent 子树入口）

> 本目录只放**仓库治理**脚本：守卫与声明，防的是仓库因 agent 而变形——路径泄漏、密钥入库、
> 文档膨胀、文档与事实脱钩。业务与验证探针在 [`client/scripts/`](../client/scripts)（信任分级见其 `README`），两者分治。
> 红线全表在仓库根 `AGENTS.md`；洗文口径与行数上限的域规则在 [`docs/AGENTS.md`](../docs/AGENTS.md)。

## 脚本（三件套，`<域><动作>.mjs`；Guard 族挡提交，报错自带修法）

| 脚本 | 拦什么 |
|---|---|
|                                    | 文末「跟踪：」声明的路径缺失 = 拦；被跟踪事实变了而声明文档没动 = 提醒不拦；引用向上（祖先）或出仓 = 拦 |
|                                      | 绝对路径（三形态，只扫文档/配置扩展）与 [API](../server/docs/API.md) key（八类，扫全部文本源）= 拦；密钥命中不回显；`<占位符>` 豁免 |
|                                    | Markdown 行数超上限 = 拦（入口类硬上限、其余 800；上限表见其头注，动笔前先登记） |

## 门控链（pre-commit；clone 后一次性激活 `git config core.hooksPath .githooks`）

`set -e` 串联：docIndex hook → repoGuard → docGuard，任一失败即中止提交。`--no-verify` 是
人类的绕行特权，agent 不用——门控为纪律而设，不是安全机制。体检：各脚本 `--report` / `check`。

## 路径红线（repoGuard 的口径依据）

- 所有路径一律仓库相对：命令示例从仓库根运行；指代仓库根写 `<仓库根>` 占位。
- 引用仓库外文件属越权动作：改写为指认来源的相对引用，或删除。
- 密钥检出 = 立即移出并轮换；占位符（`<二级令牌，可空>` 这类）是文档示例的合法形态。

## 路径即跟踪（docIndex 的口径依据）

- **有路径就算跟踪**：文档内任何路径形提及（md 链接、反引号、裸路径，含代码块内工具路径）
  都是对该文件/目录的跟踪边，无显式语法。被引用文件进了暂存区而引用它的文档没动 → commit
  时漂移提醒（不拦截）。解析顺序 = 文档目录 → 各级祖先 → 仓库根 → [`client/`](../client)/[`server/`](../server) 包根；
  单段路径（根层泛指）、glob/模板、kookit submodule、gitignored 不作边。
- **引用方向只管 md 链接**（导航语义）：禁止向上祖先、允许平级或子一级；路径提及非导航。
- **失效引用探针**：已知根段开头（[`client/`](../client) 等）而解析失败的提及 → check 模式 notice——
  文档与现实的脱钩从这里显形，发现即修。
