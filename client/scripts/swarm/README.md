# 蜂群测试（单机 服务-客户端 测试机制）

> 用户 立项："多几个客户端……用命令行和脚本模拟交互行为，模仿中小房间的流量，
> 不然这些问题就必须要在实机上试出来。" **覆盖边界（立项时对齐）**：同步逻辑 / 协议 / 传输适配器；
> 前提假设 = **交互界面如约工作**（渲染、UI、IPC 桥不进蜂群 —— 真窗口探针与手感另层负责）。

## 它是什么

- **roombot**（`roombot.ts` → esbuild 打包成 `roombot.cjs`）：一只机器人客户端。把**真实的核心层**
  （`WsNetAdapter` 传输适配器 + `RoomSession` 同步用例 + `FingerprintService`）原样搬进纯 Node 进程，
  渲染端口换成脚本化假件（按节奏吐位置、`getOpenBook` 返回与房间 edition 同指纹的合成书）。
  无书进入（`fingerprint: null`）→ 用 join-ack 的 edition 造合成书 —— 不需要任何真实书文件。
- **swarm.cjs**（编排器）：一条命令做完——编译机器人 → 编译并起**一次性 server**（临时数据目录）
  → REST 领 token / 建房（合成 edition）→ 撒 N 只机器人 → 按语义事件断言 → 收尾。退出码 = 结论。

```bash
npm run swarm                          # 默认 4 只 / 9 秒
npm run swarm -- --bots 8 --duration 12000
```

角色分工（编排器内置）：`bot1` = 翻页手（900ms 一页）、`bot2` = 聊天手（1.6s 一句）、
`bot3` = 退房者（中途离房）、其余 = 围观者。机器人数 ≤ server 每房上限 20。

## 断言（全挂在语义事件上，不比拼毫秒 —— 洪泛测试的时序教训）

| # | 断言 | 验的是什么 |
|---|---|---|
| A1 | 每只都进房且见过满员快照 | 进房链路 + presence 增长路径 |
| A2 | 翻页手的位置广播到其余各 ≥3 次；翻页手**零回声** | "除发送者外"转发语义（[TODO](../../../TODO.md) 里"三人以上未验"那条的机制化） |
| A3 | 聊天其余每只都收到；聊天手收到自己的回执 | chat 广播 + server 权威回执语义 |
| A4 | 退房者离开后其余快照减一且名单干净 | 离房广播 / 不残留（[TODO](../../../TODO.md) 多人补验①） |
| A5 | 无 SYS[error] / fatal | 任何意外失败都算蜂群失败 |

## 战果（机制自身的价值证明）

**首跑即抓出一个真实跨端 bug**：server 的 `room.presence` 载荷发**裸数组**，client 按
`{members: [...]}` 解析 —— 两侧各自自洽，真客户端的成员快照在 join-ack 之后恒为空
（位置派生 / 离房清理 / 跟随全部失效）。已修：server 包 `{members}`（v0.2.2），client 双形状归一
（`normalizePresenceMembers`）。这正是蜂群存在的理由。

## 已知边界与注意

- **8 只首跑出现过一次偶发失败**（最后一只像在空房里），复跑三次未再现 —— 可疑启动竞态，
  未定位；复现时保留全量输出（`> log 2>&1`，`--quiet-out` 可静默逐行回显）再查。
- 同机多机器人**必须各自显式 `--token`**（7 位字母数字）；绝不能依赖 `TUREAD_DEV_MEMBER_TOKEN`
  环境变量（那是进程级全局，多只同进程会互相顶号）。编排器已按 `SwarmNN` 自动分配。
- server 每房上限硬编码 20（[`cmd/server/main.go`](../../../server/cmd/server/main.go)）—— 蜂群规模别超；要更大房间先改 server。
- 机器人绕过了 IPC 桥与渲染进程 —— 那两层的机械验证靠 `TUREAD_DEV_PROBE=room` / `room-peer`
  （真窗口），蜂群不替代它们，也不替代人眼手感。
