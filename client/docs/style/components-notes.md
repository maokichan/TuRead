# §5.10 笔记管理（跨书）视图

> 本页承载风格基线 §5.10。形态与契约 = 功能总纲 §12；
> 数据口径 = 契约总纲 §4.4 读模型。本节只定**视觉语汇**。
> 参考对象 = **书库**：笔记管理是书库的"同族视图"（状态栏结构、视图切换、
> hover 口径、相对时间全部沿用），**不新造语汇**。

**「閱讀」统计段（寄生于「筆」列表顶部，全局口径）**：**贡献图** = 9px 格、
列流（列 = 周）、`--accent` 的 color-mix 透明度 5 档（25/45/70/100 + 空格 `--panel-2`；
**不引新色相**，[tokens](tokens.md) 页 §3.4 纪律）、今天 1px `--border` 描边；**摘要行**（今日/本週，12.5px muted）
+ **Top 榜行**（序号注脚 + 13px 书名〔长题 Marquee，目录同款〕+ 右对齐时长）。
两档布局：`card`（纵排）/ `page`（全宽两栏：图+摘要在左、榜在右，榜列 1px 左分隔）。
格子/榜行 v1 无交互（不做假交互）。纯视图 `ReadingStatsView`（样张挂 mock）与取数段
`ReadingStatsSection` 分离（[`client/src/renderer/src/components/ReadingStats.tsx`](../../src/renderer/src/components/ReadingStats.tsx)）。

**视图**：**只留瀑布流**（按列装箱，最短列优先；仍是时间倒序的视觉流）——
網格已退役（笔记区重构，用户定：两种排列都没组织起"笔记属于书"的关系；
按书的组织归**详情轴**，列表只做时间流）。`NoteView` 类型随之退役。

**列与尺寸（列宽固定、只变高）**

- 列宽固定 **`--note-col-w`（240px）**，列数随窗口自适应
  （`repeat(auto-fill, minmax(var(--note-col-w), 1fr))`，与书库网格 auto-fill 同口径）。
  **宽度不随内容变** —— 同一条笔记在不同窗口下换行一致，中文行宽可控。
- **高度由内容自然决定**，但**两头有界**：
  - **主次上限**（用户定）：**主方 ≤8 行、副方 ≤2 行** —— 批註為主 = 批注 ≤8 行、
    摘录 ≤2 行；摘錄為主反之（超出省略号收尾）。两边都有界。
  - **最小高度 = 元行 + 一行摘录** —— 否则瀑布流会碎成参差毛刺。
  - ⚠ 没有上限的话，一条 2000 字批注会变成一屏高的卡（这是"高度随内容变"的边界条件，不是例外）。

**卡片 = 纯文字块**：**无边框、无底色、无阴影、无圆角**（P1/P3）。
书库的封面格有 1px 边框，是因为**图需要槽**；笔记卡片没有图，**不该有框架**。

**容器边界可显形**：卡片盒与网格项盒**各有一条常驻 1px 边框**，
颜色走两个 token（`--note-card-edge` / `--note-flow-edge`，默认 `transparent`）——
以后视觉上发现问题时，**改一个值就能把边缘改出来**（或给任意祖先挂 `.note-edges`）。
- 网格项盒（`--note-flow-edge`）是瀑布流里**"跨行盒"的真实高度**：排查装箱问题时看它，
  能同时读出"内容高度 / 精确到的 8px / 余量"三者。
- ⚠ **显形不会引起重排**（全局 `box-sizing: border-box`）—— "显示边界"这个动作本身
  不能变成被观察现象的新变量。

```
▪ 書名 · 節 12                          3 天前     ← ① 元行：标记块 + 出处 + 相对时间（11px --muted）
「蛋白質攝入與肌肉合成的關係」                         ← ② 摘录：**加引号**（书里的话）
這裡說的是每公斤體重 1.6g，我要回去核對劑量。            ← ③ 批注：自己写的话（`body` 空 → 整行不出现）
```

**文字层级可切换**（两档、分主次、**默认「批註為主」**）

| 档 | 摘录 | 批注 |
|---|---|---|
| **批註為主（默认）** | 13px `--muted` | 14px `--text` |
| 摘錄為主 | 14px `--text` | 13px `--muted` |

- 差别**只有字号 + 颜色**两处：P2 一套字体、中文只有 Bold 切面 → **不做字重对比**。
- **引号是"这是书里的话"的唯一标记**：摘录一律 `「…」`；不引号 = 自己写的。
- 筛选为「劃線」时（无批注）层级切换**禁用**（opacity-30）—— 没有第二层可排。
- ⚠ **判据是 `body` 是否为空，不是 `kind`**（画完线后补 body，那这就是批注；而"加批註但没写字"
  的 `kind='note'` 又会 body 为空）。

**标记块 = 功能信息**（这条是什么色）：8×8 + 1px `--border-soft` 边（`.note-card__mark`，
与阅读器笔记行的 `.note-row__mark`〔9×9〕同口径；shell 页 §5.2 例外⑤）。
**禁止**色条 / 彩色边框 / 彩色背景。

**选中态（1px 描边档）**

- 选中 = 卡片外扩 **8px 内边距**的 **1px `--accent-ring`** 矩形（**直角，不加圆角** —— 矩形是选中标记，
  不是容器外观）。对齐书库网格的选中色（书库那处是 `border` + `ring` 双层，因为它本来就有 1px 边框）。
- ⚠ **卡片常驻 8px 内边距**：否则选中加框会挤动文字、整片瀑布流重排（**视觉抖动**）。
- ⚠ 这条落在 shell 页 §5.2 例外清单**之外**（"给纯文字块加框"）。按风格基线 §7 纪律：
  **单 commit 可回退**，实测若与 P1 冲突，回退到**元行套负片块**（`--negative-*`，面积小、不刺眼；
  新增负片用途先改 shell 页 §5.5）。
- **单卡选中**（不做多选）。键盘（方向键移焦点 / Enter 跳转 / Delete 刪除）随**意图层**收编，见唯一待办清单。

**动作：卡片右键 = 挂载线菜单**

- **形态复用** [`client/src/renderer/src/components/ContextMenu.tsx`](../../src/renderer/src/components/ContextMenu.tsx)（挂载线 + 自线下生长，
  无圆角/无阴影/无卡片底）。**语义按域**（已定并再次确认：右键在书库 = 文件管理、阅读器 = 标记/批注、
  **笔记管理 = 笔记处理** —— 右键在不同功能组件里语义不同）。
- 项：`跳轉` ／ `複製批註`（**仅 `body` 非空时出现**）／ `刪除`。
- **不设卡片内 hover 动作区**（卡片信息量不比书籍，右侧动作列**取消** → 卡片保持零 chrome）。
- **鼠标分工**：**单击 = 选中、双击 = 跳转**（与书库资源管理器语义一致）。
- ⚠ **用词纪律**：书库的「**移除**」= 只删索引、**不删源文件**；
  笔记的删除是**真实删除** → 一律写「**刪除**」，**两词不得混用**。确认弹窗
  （[`client/src/renderer/src/components/ConfirmDialog.tsx`](../../src/renderer/src/components/ConfirmDialog.tsx)）写明**不可恢复**，且**不提供"下次不再提示"**
  —— 不可逆动作不能免确认。

**底部状态栏（复用书库结构）**：`footer` + `border-t` + `pt-4`，元素**统一左对齐**；
文字按钮 22px + 字距 `0.08em`（`.text-action--lg` / `.view-switch`）。

| # | 控件 | 形态 |
|---|---|---|
| 1 | **视图切换** `網格 ⇄ 瀑布流` | `.view-switch` + **三角负片** + 闪屏动画（与书库同款，shell 页 §5.1） |
| 2 | **筛选** `批註 → 劃線 → 全部`（默认**批註**） | 单按钮**三态循环**（显示当前值，点击切下一个）；**不带三角、不加动画** |
| 3 | **层级** `批註為主 ⇄ 摘錄為主` | 单按钮两态循环；「劃線」筛选下禁用 |
| 4 | **计数** `128 條`（筛选后） | 12px `--muted`。⚠ 与书库"不显示书目数量"**不同**：**筛选计数是筛选器的必要反馈**（"筛出来多少条"），不是装饰性统计 |

- **只有视图切换带三角负片**：三角的职责是"引导点击切换视图"（shell 页 §5.1）；其余是状态/筛选，不带。
- **作用域切换已退役**（用户 定：按库分类不是笔记区的工作，库状态只在书库页；列表恒全部笔记——原「當前庫 ⇄ 全部庫」按钮删除，查询不传 `libraryId`）。
- **空态（缺失要可见，不静默）**：一行静息淡度文字；且**当前筛选是「批註」时必须报出被隐藏的数量**：
  「還沒有任何筆記」／「沒有符合條件的筆記」／「批註 0 條 —— 有 37 條劃線未顯示」。

**检索入口 = 底面全局搜索·笔记作用域**（搜索住底面顶条带；接线 = 功能总纲 §12.8）

- 关键词对 `excerpt` + `body` 做**子串**匹配（`NoteQuery.text`；v1 = `LIKE`，数据建模 §5 问题 6）。
- `Ctrl+F` 聚焦（全局输入框，[`client/src/renderer/src/features/chromeSearchBus.ts`](../../src/renderer/src/features/chromeSearchBus.ts)）、`Esc` 清空复用。

**窗口化与"刷新"成本（已量化、已实现）**

| 指标 | **窗口化（现行）** | 全量（对照） |
|---|---|---|
| `commitMs`（首屏） | **22 ms** | 519 ms（该轮 rafGap=138ms，偏高） |
| `settleMs`（布局收敛） | 324 ms | 984 ms |
| `refreshMs`（整片重渲染） | **21 ms** | 163 ms |
| **DOM 卡片数** | **42 / 1000** | 1000 / 1000 ← **与环境无关的硬事实** |

**结论**：**窗口化保留** —— 理由不是某个计时数字，而是"**DOM 节点与观察器数量不随规模增长**"
（42 vs 1000，且每个卡片挂一个 `ResizeObserver`），以及有效计时下首屏 22 ms vs 519 ms。
有效 A/B 的跑法与探针计时口径（隐藏窗口不出帧 → rAF 计时假高，探针需关后台节流 + 出帧 + 计时环境自检）
见[acceptance.md](acceptance.md)§8.0。

**实现（已落地）**：[`client/src/renderer/src/components/noteLayout.ts`](../../src/renderer/src/components/noteLayout.ts)（**纯函数、零 DOM、有单测**）负责
装箱 + 按列二分；[`client/src/renderer/src/components/NoteFlow.tsx`](../../src/renderer/src/components/NoteFlow.tsx) 只渲染视口 ± overscan。
- **自己装箱**（最短列优先 + 绝对定位）而非 CSS grid 的 `span`：窗口化的前提是
  "**不渲染就知道第 i 条在哪**"，而 grid 的自动布局把位置算在浏览器里、取不回来。
- 一个装箱器服务两种视图：網格 = 高度取齐（等高行），瀑布流 = 自然高度。
- 未测量的条目用文本长度估算位置（首屏不留空白），挂载后 `ResizeObserver` 实测纠正。
- 实现期踩到并修掉的两个真坑（流原点换算 / 测量反馈级联的 8px 量化 + 16px 死区）**留在代码注释里**。

**配套纪律**（与窗口化是两件事，缺一不可）：
- **检索防抖 ~200ms**（`NoteQuery.text` 的输入侧）：检索逐键 setState，不防抖就是"每字符一次筛选 + 重渲染"。
- **刷新粒度**：激活时重读 = 重新查询（亚毫秒）+ 只重渲视口；筛选/检索变化 = 只重查询、
  **不重建滚动容器**；切视图（網格 ⇄ 瀑布流）= 滚动归零（与书库 `resetKey` 同口径）。

⚠ 回归防线：`[client/scripts/style-gallery/smoke.cjs](../../scripts/style-gallery/smoke.cjs) --scale=N`（可加 `--no-window` 做对照）读
`window.__notesScale`；要求**卡片数与 `commitMs` 不随 N 线性增长**（N=1000 时约 40 张 / 几十毫秒）。
