# 渲染层风格基线（Style Baseline）

> 归属：**client 专属**。权威范围：`client/src/renderer/**`（UI 外壳 + 展示组件 + `styles.css`）。
> **不约束** core（domain / ports / usecases / adapters）——风格是外壳的事，端口契约见 `CONTRACTS.md`。
> 状态：**生效中**（当前修订 = §10 里的 **v1.7**）。本文是渲染层开发的**准则**：新组件先读本文，再动代码。
> 冲突裁决顺序：本文 > `FEATURES.md`（功能划分）> 组件内注释。改本文 = 契约先行，同 commit 更新。
> 登记位置：`MAP.md` 关键文档 §13；红线「渲染层开发先读本文」。

---

## 1. 风格定性

**文字即界面（typographic chrome）**：界面用"排印过的文字"承担导航、动作与状态，
把字体（而非边框、图标、色块）作为主要的视觉语汇。

三个来源，缺一不可：

| 来源 | 提供什么 | 本项目的落点 |
|---|---|---|
| 排版优先（iA Writer 谱系） | "chrome 可以不存在"的哲学；用一套字体解决专注 | 无顶栏/无 logo/无菜单栏；文字按钮 |
| 瑞士国际主义（栅格 + 层级） | 层级靠字号/字重/留白，而非颜色与装饰 | 灰阶 token + 单一 accent |
| 中文排版规范（赫蹏 / jlreq） | 汉字与西文混排、标点、行距的**硬规则** | §4（本基线的核心增量） |

> 现状（v0.1.11 收口后）：书库/阅读器/房间/设置的动作入口已统一为文字按钮（`.text-action`），
> 边框只剩输入类与浮层两类例外；本文的目的从"消灭两套语汇"转为"守住一套语汇"。

## 2. 五条原则（冲突时按序裁决）

- **P1 文字优先**：功能入口、动作、状态**优先**以排印过的文字呈现。边框/图标/色块是**例外**，
  必须在 §5 的例外清单里列明；新增例外要改本文。
- **P2 一套字体**：界面 chrome 只用**一套字体**（西文 Times New Roman + 中文源流明體，§3.1）；
  **阅读器正文由 kookit / 电子书决定，基线不干预**。字体不承担层级，层级交给 §3.2 的字号。
- **P3 层级靠排版**：字号 → 字重 → 字距 → 行距 → 留白。颜色只做"**一次**强调"，不承担分类。
- **P4 内容优先**：chrome 可消失。不设常驻顶栏/logo/状态栏（诊断日志在设置里）。
- **P5 动效克制**：一屏一动作，同一时刻至多一个关键帧，时长 ≤ 650ms，无弹跳/无缩放。

## 3. 令牌（唯一来源 = `styles.css`）

**组件内禁止写死 hex/rgba/字体名**，一律走 token 或 Tailwind 的 `var(--*)` arbitrary value。

### 3.1 字体（2026-09-09 起：**全局统一**）

**界面 chrome 只有一套字体**：西文/数字 = `Times New Roman`（印刷体），中文 = 源流明體（打包，OFL 1.1）。
实现：`--font-ui: 'Times New Roman', 'GenRyuMin TW', …`，`body` 继承；`--font-serif-cn` 为同值别名。

> ⚠ **顺序不可反**：Times New Roman 无 CJK 字形 → 汉字自动回退到源流明體；
> 若把源流明體放前面，它子集里的拉丁字形会抢走西文。
> ⚠ **阅读器正文不在此约束内**：kookit 在 iframe 内自建样式，宿主字体不会继承进去（§4.3）——
> 电子书的字体/字号由引擎与书本身决定，基线只保证"不改它"。
> ⚠ 源流明體只有 Bold 一个切面 → 中文**不能做字重对比**，层级只能靠字号/字距/颜色。

| 声部 | 字体 | 用在哪 |
|---|---|---|
| 统一界面字体 | Times New Roman + 源流明體 | 全部界面文字：导航、按钮、标题、字段、状态、日志 |
| 阅读正文 | 由 kookit / 电子书自身决定 | 阅读页 iframe 内 —— 基线**不干预** |

> 原"三声部"（衬线 / 无衬线 / 等宽）已按用户决定收敛为**单一字体**。
> `--mono` 保留为**同值别名**（避免大范围改动）；若要恢复"技术数据等宽对齐"，
> 把该 token 改回 `monospace` 栈即可——但那时要重新评估与 P2 的关系。

### 3.2 字号阶梯（px，白名单外禁止）

`11 · 12.5 · 13 · 14 · 15 · 17 · 18 · 19 · 22`，以及封面自适应 `10–120`（`FittedTitle` 二分拟合）。
`22` 仅用于书库底部状态栏的两个文字按钮（`.text-action--lg` / `.view-switch`）。

| 用途 | 字号 | 声部/字重 |
|---|---|---|
| 技术数据、辅助说明 | 11 / 12.5 | 400 |
| 表单、正文控件 | 13 | 400 |
| 面板标题 | 14 / 15 | 700 / 600 |
| 列表标题 | 17 | **700 但视觉不加粗**（现状，见 §5.4） |
| 动作文字按钮 | 18 | 700 |
| 侧边栏符号 | 19 | 700 |
| 状态栏文字按钮 | 22 | 700，字距 `0.08em` |

### 3.3 字距 / 行距 / 留白

| 项 | 基线 |
|---|---|
| 字距 | 中文界面 `0`；文字封面 `0.01em`；小标签/大写标签 `0.6px`；状态栏文字按钮 `0.08em` |
| 行距 | 界面 `1.35–1.6`；文字封面 `BASE_LEADING 1.02` → 余量分给行距，上限 `2.4` |
| 留白刻度 | `4 / 8 / 12 / 16 / 20`（Tailwind `1/2/3/4/5`），不出现奇数间距 |
| 圆角 | 小控件 `rounded`；行/按钮 `rounded-lg`；面板 `rounded-xl` |
| 阴影 | **无阴影**（抽屉已于 2026-09-09 去掉 `shadow-2xl`）；层级靠底色与留白 |
| 动效 | 全应用**唯一**动画 = 视图切换 900ms（`view-switch-flash`）；**动画期间按钮 disabled**（防连点导致动画不出现） |

### 3.4 颜色

- 基底**灰阶**：`--bg / --panel / --panel-2 / --border / --border-soft / --text / --muted`。
- **单一强调**：`--accent`（+ `-soft/-strong/-ring/on-accent`）。强调只用于"当前选中 + 主动作"。
- **语义状态色**：`--ok / --warn / --err`（+`-border`）——只表达状态，不做装饰。
- **主题模型（2026-09-11 规正，权威 `core/domain/theme.ts`）**：**2 主题 × 2 模式** ——
  主题（tone）＝ 纯色（黑灰白）｜羊皮纸（暖棕）；模式（mode）＝ 深｜浅。数据层沿用四值
  `dark=纯色·深 / light=纯色·浅 / sepia-light=羊皮纸·浅 / sepia-dark=羊皮纸·深`。
  四套 token 组（`styles.css`）：`:root`＝纯色·深，`[data-theme=light|sepia-light|sepia-dark]` 各一套。
  「跟随系统」只作用于**模式**，在**所选主题内**解析。**新增取向 = 复制整套 token**，不允许局部覆盖。
- **阅读页跟随模式**：`--page-bg/--page-text` 是正文页的纸色 —— **深色模式必须用该主题的深色纸**（纯色·深＝深灰纸），
  不再"暗色主题仍白纸"（2026-09-11 改，用户定：夜间模式与深/浅选择挂钩）。
  非 PDF 正文的深色渲染由 `IRenderService.applyTheme` 注入（`CONTRACTS.md` §4.1）；浅色不注入、保留书的外观。
- **阅读页的"桌"与"纸的边"（2026-09-11 v0.5，四套主题各一组）**：`--desk-bg`（纸外背景）+
  `--page-edge`（纸的 1px 边）。**内容与背景靠颜色区分**——桌比纸暗一档，纸再有边线；
  不用阴影/圆角。新增取向时这两项随整套 token 一起复制。
- **阅读页布局尺寸 + 视图列宽（同一处登记，避免多处硬编码漂移）**：`--sidebar-w`（侧边栏宽度，AppShell 与挂载线几何共用）、
  `--read-width`（正文列宽，由「设置」写到 documentElement）、`--page-pad-x`（**纸内边距** = 正文到纸边的距离，
  由适配器注入 `body{padding-inline}`）、`--toc-line-top`（挂载线纵向位置）、
  **挂载线两挂件的镜像几何三件（2026-09-16 新增，替代原 `--toc-line-w` / `--reader-panel-w`）**：
  `--rail-panel-w`（**两侧共用**的面板宽度上限 → "同宽"）、`--rail-gap`（面板外缘到纸边的呼吸位）、
  `--rail-panel-h`（**两侧共用**的高度上限 → "同高"）；另有两条**算式**（`--rail-shift` / `--rail-w-cap`）
  在 `styles.css` 的挂载线一节就地声明（⚠ 不能进 `:root`：`var(--read-width)` 要取最近祖先的值、
  `50%` 要在使用元素上解析，否则样张里缩小纸宽会失真）、
  `--toc-veil-rest`（目录静息遮罩不透明度，越大越淡）、
  **`--note-col-w`**（笔记管理·瀑布流/网格的**列宽**，固定 240px；列数随窗口自适应，见 §5.10）。
- **负片（反色矩形块）**：`--negative-bg: var(--text)` / `--negative-text: var(--bg)` ——
  派生自各主题的 text/bg，所以四套取向自动成立。语义 = 文字块成为"纸的反面"
  （页面白 → 块黑字白）。**只允许详情抽屉的文字块使用**（§5.5）。
- **笔记/划线四色 `--note-{yellow,green,blue,red}`（2026-09-14 新增，v1.2）**：
  **语义内容标记色**，性质同 `--ok/--warn/--err`（表达内容状态，**不做装饰**）——
  它不是"引入色相做美化"，而是"读者标记内容"这一功能本身需要可区分的色。
  四套取向**各给一组具体值**（不派生：同一色在深纸与浅纸上不可通用）。
  - 值只在 `styles.css`（颜色唯一来源）；**库内只存语义名**（`Note.color` = 语义名，非 hex，
    见 CONTRACTS §2 `NoteColor`）。
  - ⚠ **约束（决定取值口径）**：kookit 对非 PDF 高亮统一渲染为 `rgba(<该值>, 0.8)` 并叠在正文上
    → **深色取向必须用低亮度高饱和**，否则浅色块压浅色字糊成一片。故：
    纯色·深 = 冷调压暗（如 `#6b5a1f`）/ 羊皮纸·深 = 暖调压暗；浅色两套才用经典荧光笔色。
  - ⚠ 适配器**不能**把 `var(--note-red)` 传给引擎：高亮 span 长在**书的 iframe** 内，
    宿主 CSS 变量不跨文档继承 → 由适配器解析成具体值再内联（`kookitRenderAdapter.resolveNoteColor`）。
    宿主的色板 UI 本身照常用 `var()`。
- **选区 `--selection-bg`（2026-09-14 新增，v1.4）**：默认选区是**浏览器系统蓝**，与"纯色取向不引入
  色相"直接冲突（用户 2026-09-14 指名"选中文字仍是系统蓝，看上去并不美观"）。
  四套取向各一组：纯色两套 = **中性灰淡扫**（不引入色相，同该取向口径）；羊皮纸两套 = **暖调淡扫**。
  - **只给背景、不给前景色** —— 做成低饱和"淡扫"而非反色块：阅读更温和，且不必担心在深色纸上把
    正文色配错。
  - 两处都要覆盖，**它们是两个文档**：① 宿主侧可选区域（输入框等）→ `styles.css` 的全局
    `::selection`；② **书文档内的正文** → 宿主 CSS 跨不过文档边界，必须由适配器读同一 token 后
    **内联注入**（`buildReaderCss` ④）。缺 token 时告警并回落浏览器默认（不静默）。

## 4. 中文排版（本基线核心增量）

> 此前源流明體只被当"好看的标题字体"用，汉字与西文混排、标点、段距**没有任何规则**。
> 参照：[赫蹏 heti](https://github.com/sivan/heti)（中文排版规范实现）、
> [W3C jlreq](https://www.w3.org/TR/2012/NOTE-jlreq-20120403/ja/)（日文组版要求，CJK 通用）、
> [Typotheque · CJK 組版](https://www.typotheque.com/articles/typesetting-cjk-text-jp)。

### 4.1 硬规则

1. **中西混排间距**：汉字与西文/数字之间应有约 `1/4 em` 空隙。
   优先用 CSS `text-autospace` / `text-spacing-trim`；**浏览器不支持时不做处理**，
   **禁止**用 JS 往文本里插空格（污染数据、破坏复制与搜索）。
2. **标点**：中文用全角标点；数字/英文用半角（不写全角数字）。
   行首禁则（`、。，）」` 等不出现在行首）、行尾禁则（`（「` 不出现在行尾）：
   用 `line-break: strict` + `word-break: normal`；`text-spacing-trim` 支持时启用挤压。
3. **行宽**：中文正文 **28–40 字/行**（超出即增大容器内边距或收窄版心）。
4. **行距**：中文正文比西文松——`1.6–1.8`；界面文字块按 §3.3。
5. **段距 vs 首行缩进：二选一，不得并用**。
   本项目默认 **段间距、不缩进**（界面与阅读页一致，避免"半格缩进"错觉）；
   若将来提供"纸书排版"档，才启用 `text-indent: 2em` 且段距归零。
6. **纵排预留**：容器抽象不得假设横排（避免把宽度写死成"字数 × 字号"）；
   `writing-mode: vertical-rl` 的实装**不在 v1**，但新组件不得阻断它。

### 4.2 落地位置

所有中文排版规则集中在 `styles.css` 的一个区块（`.cjk-body` / `.cjk-ui` 两个类），
**组件不自行设置** `letter-spacing` / `text-indent` / `line-break`。

## 5. 组件规则

### 5.1 必须用文字（P1 默认）

- 导航：侧边栏、视图切换、标签页切换。
- **侧边栏选中态 = 负片块**（`.feature-nav--active`，反色），**不用圆角按钮/底色/描边**
  （2026-09-09 用户定）；未选中 = 单色汉字，hover 只变色温。
- **列表类导航一律是纯文字行**：阅读器目录（`TocPanel`）、房间大厅（`RoomRow`）——
  无边框、无底色、无圆角、无分隔线，靠**留白分行**；hover 只做色温变化。
- 主要动作：導入、发送、打开阅读、创建房间、进入。
- 状态与计数：`3 本`、`提取封面 2/5`、连接状态、房间号。

**主/次动作的区分靠色温，不靠边框**：主动作 `--accent`，次动作 `--muted` → hover 升为 `--text`。
样式统一定义在 `styles.css` 的 `.text-action` / `.text-action--primary` / `.text-action--danger`，
**组件只挂类名**，不得自行写字号/颜色。

**三角负片标记（唯一例外）**：只有**「视图切换」这一个功能**的按钮带右下角三角
（`.view-switch::after`，`mix-blend-mode: difference` 的**真负片**）——
**书库底部状态栏**与**笔记管理底部状态栏**（2026-09-16 扩，见 §5.10）各一个；
两处的**行为也共用**：900ms `view-switch-flash` + 动画期间 `disabled`。
它**压在文字本身上**（不是贴在按钮外侧）——压到的字形会被反相。
理由：该按钮的职责是**引导用户点击切换视图**；其他文字按钮（状态、筛选、循环切换）**都不需要**。
新增带三角的按钮必须先改本文。

**状态栏布局（2026-09-09 定）**：底部状态栏**所有元素统一左对齐**（不再左右对称分布），
分割线随内容区宽度铺开，`pt-4` 让分割线相对内容区上移。
两个文字按钮放大到 22px + 字距 0.08em（`.text-action--lg` / `.view-switch`）。
**不显示书目数量**（无关紧要，2026-09-09 用户定）。

**按钮盒必须紧贴文字**：`.view-switch` 用 `padding: 0` + `line-height: 1.1` + `width: fit-content`。
原因：动画的背景块画在按钮盒上 —— 盒若被 padding 撑大，文字就"填不满背景"，
三角标记也会落到字外面（2026-09-09 修）。**任何带背景动画的文字按钮都要遵守这条。**

### 5.2 允许边框/底色的例外（必须在此列明）

| # | 例外 | 理由 |
|---|---|---|
| ① | **输入类**：`input` / `textarea` / 下拉 | 可点区域必须可见，文字无法表达"此处可输入" |
| ② | **破坏性动作**（移除、断开、删除）：文字形态 + `--err` 色 | 仍是文字按钮，**只允许用语义色**，不加红框红底 |
| ③ | **浮层**（详情抽屉、导入菜单、**阅读器侧边栏贴缘按钮**） | 需要与内容区分层级。**抽屉已于 2026-09-09 去掉边框/阴影**（§5.5），只剩「导入菜单」保留浮层边框；**目录挂载列表容器全透明**（§5.8，2026-09-11 改） |
| ④ | **状态胶囊**（`StatePill`） | 语义色点 + 文字，属于 §3.4 的状态色 |
| ⑤ | **色块 = 功能信息**（原「选区色板」，2026-09-14；**2026-09-16 扩**） | 规则：**颜色本身就是信息**时才允许色块，且**文字仍承担"叫什么"**（不写"叫什么"的纯色圆点不允许）。现行三处：① **右键菜单的色块项**（`ContextMenu.swatch`：这一项落哪种标记色）；② 阅读器左挂件笔记行的**标记块**（`.note-row__mark`，9×9 + 1px `--border-soft` 边）；③ **笔记管理卡片的标记块**（同 ②，见 §5.10）。⚠ 原 `SelectionPalette`（正文选中后浮出的四色板）已随 v1.3 被右键菜单取代而**删除**，本条不再描述它。⚠ **禁止把色块升级为色条 / 彩色边框 / 彩色背景** —— 那是装饰（P3） |

### 5.5 负片（反色矩形块）—— 仅两处

**用途（2026-09-09 定）**：① 书库详情抽屉的标题与字段；② **侧边栏选中项**（`.feature-nav--active`）。

**抽屉（`BookDetailPanel`）—— 平面结构（2026-09-09 用户定）**

```
┌────────┬───────────────────────────────┐
│        │ ① 标题条（负片，过长自己滚）    │  ← 三行 = 封面高度三等分（32px×3），
│ 封面    │ ② 数据行（格式·大小·时间·路径）  │     左对齐「封面右缘」，撑满抽屉宽度
│ 64×96  │ ③ 指标行（已读 42%｜3 天前｜共 —）│
├────────┴───────────────────────────────┤
│ 描述块（满宽负片）                        │
└────────────────────────────────────────┘
```

- **封面保持 2:3 原始比例（64×96）**：三行各 32px、合计正好等于封面高度 ——
  **不得为了排版把封面拉伸/裁成细条**（2026-09-09 教训：`w-[72px]` + `items-stretch`
  把封面拉成 72×172，`object-cover` 裁得只剩中间一条）。
  需要更多横向空间时**调抽屉宽度**（现 280px），不要动封面比例。
- **不给任何容器加标签**（2026-09-09 用户定）：内容自己说明性质 ——
  "已读 42%" 不必写"阅读进度"，"3 天前" 不必写"上次阅读"，"共 —" 是总阅读时长占位。
  因此上一版的竖排标签（`.vertical-label`）已删除。
- **单行硬约束**：① ② 用 `Marquee`（超出才滚，绝不换行向下生长）；文件路径并入 ②。
- 外壳**完全透明**（无边框、无阴影、无底色），下层书库内容从文字块之间透出来。
- 动作按钮用 `.text-action`；**关闭按钮在底部**（Esc / 点抽屉外是主要关闭路径）。
- 占位待实现：总阅读时间、描述内容（均见 `TODO.md`）。

### 5.8 阅读器沉浸态（准则；历史见 §10 修订记录）

**原则（用户定，对应 koodo 式阅读）**：进入阅读 = 专注文本。**不必要的内容全部退场** ——
无常驻状态栏、无无用功能键、无圆角边框的"嵌入盒子"；界面上只保留需要渲染的文本内容。
两条容易做错的地方先写在最前面：**全屏的是"桌"不是"正文"**；**鼠标一动就浮出来的栏同样是状态栏**。

| 规则 | 内容 |
|---|---|
| **纸与桌** | 全屏铺开的是**桌**（`--desk-bg`）；正文在**居中的定宽「纸」**里（`--read-width`，px；档位 窄 620 / 中 760 / 寬 920，默认 **760**）。**内容与背景必须可分，而且靠颜色**（不是阴影/圆角）：桌比纸暗一档（四套主题各一组），纸再有 **1px `--page-edge` 边** |
| **纸的内边距** | `--page-pad-x`（正文到纸边的距离；档位 24/44/72）—— 适配器注入正文 `body{padding-inline}`。这是"出血"唯一的正确加厚位置（见 §5.9 表 #6 的算术约束） |
| **宿主容器 = 纸** | 滚动宿主仍是 `#page-area`（硬契约，`KOOKIT.md` §5.1/§5.8），但它现在是**纸**（定宽居中、`overflow-y:auto`），外层是**全屏桌**容器。纸宽 = kookit 的排版宽度依据（宿主 `clientWidth`）→ 改纸宽即改"一行多长"、图片缩放与分页宽度，**不需要新端口**。两侧留白 = 未来右侧容器的可增长区（§5.9） |
| **滚轮** | 落在两侧留白上也要能滚：外层桌把 wheel 转发给纸（否则鼠标停在留白上没反应）；纸内部走原生滚动，转发要跳过，否则双倍 |
| **滚动条** | "必要的器"而非装饰，**不得在用户不希望的时候影响注意力**：**2px**；静息只有 `--page-text` **10%**，**指针进入纸内**才升到 26%；**短章节整条隐藏**（判据见下）。⚠ 只写 `::-webkit-scrollbar`，**不能写标准属性** `scrollbar-width`/`scrollbar-color` —— Chromium 121+ 起写了它们就会让 webkit 规则被**整个忽略**（实测量出来是 `thin` 的 ~11px）。桌容器 `overflow:hidden`，滚动条不会跑到屏幕边缘 |
| **短章节的判据** | kookit 给文字类 iframe 的 `height` 硬留 **+300px 余量**（`handleIframeHeight`），所以"短章节也总有得滚"不是真溢出。溢出 ≤ 余量时适配器设内联 `scrollbar-width: none`（**完全不占位**：标准属性优先正好当开关用）；真溢出才让 2px 规则生效 |
| **阅读页零控件** | 书名、页码、上一页/下一页/目录/关闭**都不常驻、也不做"浮现栏"**。进度与位置不占操作面 |
| **退出** | `Esc`（键盘）；鼠标路径 = 贴缘按钮召回侧边栏 → 「書」。**不为退出在阅读页上加按钮** |
| **沉浸全屏（2026-09-13）** | `F11`（意图层 `reader.toggleFullscreen`）或设置开关（「進入閱讀器時進入全屏」，默认关）= OS 级全屏 + **标题栏整条退场**（真全屏不留拖拽区；找回 = `F11`/`Esc`）。`Esc` 分流：先收参数面板 → 再退全屏 → 再退阅读器；**离开阅读器自动还原窗口**（全屏只属于阅读态，不遗留到其他功能态） |
| **翻页** | 键盘 `←/→` `Space(分页模式)` `PgUp/PgDn`；鼠标点击左右 1/3 区域（仅分页模式）；scroll 模式滚轮。**目录开合 = `t`**，**阅读参数 = `p`**（键盘，无界面痕迹） |
| **侧边栏退场（覆盖式）** | `activeFeature === 'reader'` 时左侧图标栏隐藏；**贴左缘的按钮**点击召回。**阅读态的侧边栏是覆盖式**（`absolute` 浮在左侧桌边，**不占布局**）—— 用户定：*打开左侧菜单不应影响阅读器界面宽度*（占位式一展开会让纸右移、窄窗口下还会压窄纸、目录左缘也跟着漂）。⚠ **只给阅读态**：其他功能的交互形态需求未知，将来若第二个功能也需要，把条件扩成**显式能力标记**（如 descriptor 的 `floatSidebar`），不要散落判断 |
| **贴缘按钮形态** | 可见条**窄而长（6×160）**；按钮本体 **18×200**（比可见条**外扩一圈**）= 判定范围，方便鼠标弹出。被控对象展开（钉住）时按钮**跟着移到它的边缘**（侧边栏 → `left: var(--sidebar-w)`），永远贴边且可点 |
| **阅读参数面板（挂载线右段垂挂）** | 显示设计的入口（字号/行距/段距/纸宽/内边距/佈局）。**默认展开**（2026-09-13 用户定，废 v0.8 的"默认收起"——参数是阅读的常伴工具，不该每次伸手召唤）：点挂载线右段或面板底部「折疊」（与目录同款）开合，**折叠 = 向上收回线里**，重开书回到展示态；面板全透明、纯文字档位、发丝分割线、内容**中间对齐**、**遮罩按距离**（与目录同款）。`Esc` **先收面板**、再退阅读器 |
| **右键挂载菜单（动作区可见度，2026-09-16 用户定）** | 形态仍是"线 + 自线下方生长"（v1.3），但**动作区不再透明**：纯色底 `--panel-2` + 1px `--border` 描边，项文字 `--text`（hover → `--accent` + `--accent-soft` 底）。理由：它挂在**正文纸上**，靠"内容与背景同色"读不出来（用户原话"整个容器太透明了"）—— 见 §5.2 例外⑥ |
| **批注输入栏（2026-09-16 用户定，v1.8 改形态）** | 用户原话："**默认在底部中心对齐，作为一个纯色带边框的容器，不带任何提示词，作为焦点存在**，但操作逻辑还和现在一样"。落地 = 屏幕**底部居中**（`fixed bottom-6 left-1/2 -translate-x-1/2`，**不再跟随右键坐标**）、纯色底 `--panel-2` + 1px `--border`、**零文字**（无标题、无 placeholder、无按钮 —— 焦点态由容器 `:focus-within` 给 `--accent` 边）。操作逻辑不变：挂载即聚焦、`Enter` 提交、`Shift+Enter` 换行、`Esc` 取消。⚠ **移除既有笔记**因此只剩**右键菜单**一条路径（菜单项仍在）。⚠ 机检：样张 `smoke.cjs` 的 `composerOk`（零可见文字 + 无 placeholder + 非透明底 + 发丝描边 + 水平居中 ±2px + 挂载即聚焦） |

**目录（挂载线 + 垂挂列表）与阅读参数（底部挂件）——挂载线实体（2026-09-12 用户定）**

挂载线保持**横向**，但**延伸整个页面宽度**（`ReaderRail` 实体：左段目录挂载区 / 中段纯线跨过
正文上方 / 右段参数挂载区）：目录自线下方垂挂（形态下表不变）、**阅读参数面板挂在线右段下方**——
开合 = 点挂载线右段或面板底部「折疊」（与目录同款：居中 + 引导分割线），**折叠 = 向上收回线里**
（内容统一中间对齐；原右侧独立召唤条废除）。**低透明度与目录同款** = 遮罩按距离：文字全强度，
每行盖一层桌色遮罩，近 → 揭开、远 → 静息（`--reader-veil-rest`，缺省随 `--toc-veil-rest`）。两个挂件互不干扰（左/右分区）又同处一条线；**目录折叠时，点线（左段）=
展开目录**（线的点击职能）。快捷键：参数 `p`、目录 `t`。

| 项 | 规则 |
|---|---|
| **挂载线** | 一条**细横线**，自目录段起**延伸整个页面宽度**，是目录（左）与阅读参数（右）共同的**挂载点**（不是按钮外观、不是装饰分割线）。**线的左端 = `--sidebar-w`**（贴侧边栏右缘，靠 `__lead` 占位实现，**线不从窗口左缘起**）；左右段宽 = 面板宽（`--rail-w-cap`，两侧相同）。静息 34% 不透明度、hover 75%；**目录段可点** = 目录开合，**参数段可点** = 参数开合（折叠时的收回热区） |
| **左右镜像（2026-09-16 用户定）** | 两个挂件**以页面中线镜像**：**同宽**（都用 `--rail-w-cap`）、**同高**（都用 `--rail-panel-h` 上限）、**离中线等距**（外缘到中线 = `--rail-shift` = 纸半宽 + `--rail-gap`）。窄窗口时两侧一起收窄（仍是镜像）；**左挂件另有 `max(--sidebar-w, …)` 兜底**（侧边栏展开时不被压住）。线段与面板**同宽同侧**（算式唯一一份，在 `styles.css` 的挂载线一节）。⚠ 机检：样张 `smoke.cjs` 的 `mirrorOk`（同宽 ±1px、两侧 gap 相等 ±2px、高度上限同值） |
| **跟随当前位置（2026-09-16 用户定）** | **用户读到哪里，哪个条目就落在列表正中**（用户原话："确保目录条目索引，用户读到哪里，哪个条目就处于目录的中间位置"，且"这一点同样反应在笔记上"）。判据是**纯函数**（`components/readerFollow.ts` + 单测）：目录 = **章号 ≤ 当前位置的最后一条**；笔记 = **当前章的第一条**（本章无笔记则退化为之前最后一条）。打开/换书 = 瞬时落位，跨章跟随 = 平滑滚动。⚠ **粒度诚实**：位置只到**章**（kookit 不给章内进度）→ 章内精确到某一条已登记 `TODO.md`。⚠ 机检：样张 `smoke.cjs` 的 `followedOk`（**先要求列表真的能滚**，再量偏差 ±8px） |
| **从线上垂挂** | 展开后条目**自线下方开始、逐条向下**排列（一条条向下 ≠ 卡片/抽屉盒子），左端与线的左端对齐 |
| **容器全透明** | 条目容器**完全透明**（没有底色）。层级靠排版与留白，不靠底色（对应 §2 原则） |
| **高亮 = 遮罩按距离** | **不是 hover 改文字颜色**。条目文字给足强度（`--text`），明暗由**盖在条目容器上的一层桌色遮罩**承担：不透明度在 **`[0, 静息值]`** 之间随**条目到鼠标的距离**变化（正中 → 0 完全揭开；超过 110px → 静息 `--toc-veil-rest`），过渡 **200ms** → 鼠标移动是一段"揭开"的动画，而非开关式高亮。⚠ **不变量：远端条目保持静息，靠近只做"揭开"，绝不比静息更暗**（公式 `veil = 静息值 × (1 − 接近度)`） |
| **静息更淡** | 静息遮罩 `--toc-veil-rest: 0.74`；「折疊」按钮静息 50%、hover 100% |
| **结尾折叠按钮** | 列表末尾一个文字按钮（「折疊」），**与条目容器中间对齐**；与条目区之间有一条**引导分割线**（否则条目滚到边界像凭空出现）；收回到只剩挂载线 |
| **默认展示** | 有目录的书**默认就是展开的**；**点击条目跳转不收起**；只有用户主动「折疊」/`t` 才临时隐藏（不持久化，换书回到展示态） |
| **不遮正文的理想态** | 浮层不改变纸的位置与宽度（`position:absolute`，不参与布局）；纸够宽时目录落在左侧留白内 |

> 例外登记（§5.2 例外清单）：左右两条**贴缘召唤条**属浮层例外（可有半透明底）。
> **阅读页没有任何常驻栏** —— 进度线/顶栏这类"浮现栏"不算例外，不得再加。
> 无头自检硬契约：正文宿主保留 `id="page-area"`；侧边栏「阅读」按钮保留（`aria-label="阅读"`）供真实用户路径断言。

### 5.10 笔记管理（跨书）视图（2026-09-16 立案并实施；窗口化见本节末）

> 形态与契约 = `FEATURES.md` §12；数据口径 = `CONTRACTS.md` §4.4 读模型（v0.4.1）。
> 本节只定**视觉语汇**。参考对象 = **书库**：笔记管理是书库的"同族视图"（状态栏结构、视图切换、
> hover 口径、相对时间全部沿用），**不新造语汇**。

**视图两态**：`網格` ｜ `瀑布流`（`NoteView`）—— **没有列表形态**（用户 2026-09-16 定）。

| | 網格 | 瀑布流（**默认**） |
|---|---|---|
| 行 | **等高行**（行内卡片同高 = 内容上限高度） | 不等高，**按列装箱**（最短列优先） |
| 顺序 | 行优先（左→右，时间倒序） | 装箱，**仍是时间倒序的视觉流** |
| 擅长 | 快速扫（对齐、密度均匀） | 内容长短悬殊（**本场景**） |

**列与尺寸（用户 2026-09-16 定：列宽固定、只变高）**

- 列宽固定 **`--note-col-w`（240px）**，列数随窗口自适应
  （`repeat(auto-fill, minmax(var(--note-col-w), 1fr))`，与书库网格 auto-fill 同口径）。
  **宽度不随内容变** —— 同一条笔记在不同窗口下换行一致，中文行宽可控。
- **高度由内容自然决定**，但**两头有界**：
  - 摘录 ≤ **4 行**、批注 ≤ **6 行**（超出省略号收尾；全文跳转进阅读器看）。
  - **最小高度 = 元行 + 一行摘录** —— 否则瀑布流会碎成参差毛刺。
  - ⚠ 没有上限的话，一条 2000 字批注会变成一屏高的卡（这是"高度随内容变"的边界条件，不是例外）。

**卡片 = 纯文字块**：**无边框、无底色、无阴影、无圆角**（P1/P3）。
书库的封面格有 1px 边框，是因为**图需要槽**；笔记卡片没有图，**不该有框架**。

**容器边界可显形（用户 2026-09-16 定）**：卡片盒与网格项盒**各有一条常驻 1px 边框**，
颜色走两个 token（`--note-card-edge` / `--note-flow-edge`，默认 `transparent`）——
以后视觉上发现问题时，**改一个值就能把边缘改出来**（或给任意祖先挂 `.note-edges`）。
- 网格项盒（`--note-flow-edge`）是瀑布流里**"跨行盒"的真实高度**：排查装箱问题时看它，
  能同时读出"内容高度 / 精确到的 8px / 余量"三者。
- ⚠ **显形不会引起重排**（全局 `box-sizing: border-box`）—— 这一点很重要：
  "显示边界"这个动作本身不能变成被观察现象的新变量。

```
▪ 書名 · 節 12                          3 天前     ← ① 元行：标记块 + 出处 + 相对时间（11px --muted）
「蛋白質攝入與肌肉合成的關係」                         ← ② 摘录：**加引号**（书里的话）
這裡說的是每公斤體重 1.6g，我要回去核對劑量。            ← ③ 批注：自己写的话（`body` 空 → 整行不出现）
```

**文字层级可切换**（用户 2026-09-16 定：两档、分主次、**默认「批註為主」**）

| 档 | 摘录 | 批注 |
|---|---|---|
| **批註為主（默认）** | 13px `--muted` | 14px `--text` |
| 摘錄為主 | 14px `--text` | 13px `--muted` |

- **引号是"这是书里的话"的唯一标记**：摘录一律 `「…」`；不引号 = 自己写的。
- 筛选为「劃線」时（无批注）层级切换**禁用**（opacity-30）—— 没有第二层可排。

**窗口化与"刷新"成本（**已量化、已实现、定案 2026-09-16**）**

> 起因：用户提出"书库域吃过大规范数据刷新卡死的亏，笔记这边规划了没有"。
> 此前 `NoteFlow` 是**全量渲染**（头注里就写着"未做窗口化"）—— 属**已知未决**，本轮先测量再定。

**⚠ 先说一个必须记住的教训：第一版测量是错的，而错数字差点进了决策。**

第一版量到"整片重渲染 **1.607 s**"，据此写下"候选②（不窗口化）被否决"。复核时发现那是
**探针自身的假象**：探针的窗口是 `show:false`（**从未显示过**）→ 合成器不出帧 →
`requestAnimationFrame` 的间隔被拉到 **~850 ms**，而 `commitMs`/`refreshMs` 正是用 rAF 计的
（两次嵌套 rAF ≈ 1.7 s）。计时器不受影响，所以同样用计时器的 `settleMs` 一直正常 —— 它掩盖了问题。
**修法**：探针关掉后台节流 + `showInactive()` 让窗口真的出帧，并新增**计时环境自检**
（量空闲 rAF 间隔，> 60 ms 直接判 FAIL）。
**口径**：**探针的假数字/假阴性比 FAIL 更危险** —— 它会把真回归盖住（本轮另有一次断言假通过，见 §8.0）。

**有效 A/B**（`tools/style-gallery/smoke.cjs --scale=1000 [--no-window]`，真实组件 + 真 Electron，
1000 条，计时环境自检 `rafGap ≈ 9 ms`）：

| 指标 | **窗口化（现行）** | 全量（对照） |
|---|---|---|
| `commitMs`（首屏） | **22 ms** | 519 ms（该轮 rafGap=138ms，偏高） |
| `settleMs`（布局收敛） | 324 ms | 984 ms |
| `refreshMs`（整片重渲染） | **21 ms** | 163 ms |
| **DOM 卡片数** | **42 / 1000** | 1000 / 1000 ← **与环境无关的硬事实** |

**结论**：**窗口化保留** —— 理由不是那个假数字，而是"**DOM 节点与观察器数量不随规模增长**"
（42 vs 1000，且每个卡片挂一个 `ResizeObserver`），以及有效计时下首屏 22 ms vs 519 ms。

**实现（= 原候选①，已落地）**：`components/noteLayout.ts`（**纯函数、零 DOM、有单测**）负责
装箱 + 按列二分；`NoteFlow` 只渲染视口 ± overscan。
- **自己装箱**（最短列优先 + 绝对定位）而非 CSS grid 的 `span`：窗口化的前提是
  "**不渲染就知道第 i 条在哪**"，而 grid 的自动布局把位置算在浏览器里、取不回来。
- 一个装箱器服务两种视图：網格 = 高度取齐（等高行），瀑布流 = 自然高度。
- 未测量的条目用文本长度估算位置（首屏不留空白），挂载后 `ResizeObserver` 实测纠正。

**实现期踩到并修掉的两个真坑**（都留在代码注释里）：
1. **流不一定在滚动容器顶部** —— 第一版把 `scrollTop` 当成**流内坐标**，于是"笔记节在页面中段"
   时判定整屏都在流外 → **一张卡都不渲染**（被样张抓到）。修法：量出流在滚动坐标里的**原点**再换算。
2. **测量反馈级联** —— 切文字主次档让字号 14↔13px、卡片高度变几像素 → 位置全挪 → 可见集变 →
   挂载新卡 → 再测……修法：实测高度**量化到 8px + 16px 死区**（首次必写，之后只有大变化才动布局）。

**配套纪律**（与窗口化是两件事，缺一不可）：
- **检索防抖 ~200ms**（`NoteQuery.text` 的输入侧）：标题栏搜索逐键 setState，不防抖就是"每字符一次筛选 + 重渲染"。
- **刷新粒度**：激活时重读 = 重新查询（亚毫秒）+ 只重渲视口；筛选/检索变化 = 只重查询、
  **不重建滚动容器**；切视图（網格 ⇄ 瀑布流）= 滚动归零（与书库 `resetKey` 同口径）。

⚠ 回归防线：`smoke.cjs --scale=N`（可加 `--no-window` 做对照）读 `window.__notesScale`；
要求**卡片数与 `commitMs` 不随 N 线性增长**（N=1000 时约 40 张 / 几十毫秒）。

2. 白名单外的字号（§3.2）。
3. 衬线体使用非 700 字重（唯一豁免见 §5.4）。
4. 引入图标字体/图标库/彩色 emoji。
5. 多色强调、渐变、阴影（除抽屉）。
6. 组件内自行设置 `letter-spacing` / `text-indent` / `line-break`（归 §4 集中管理）。

## 7. 激进档与回退机制

**当前取向：激进文字化**（用户 2026-09-09 决定）——"大幅度使用文字取代，激进尝试以查看效果"。
为保证**时刻可回退**，遵守三条纪律：

1. **提交粒度 = 回退单元**：一次交付一个 commit，提交信息前缀 `style(client):`。
   回退单次：`git revert <sha>`；回退到某个时间点：`git checkout <sha> -- client/src/renderer`。
2. **逐组件推进**，不做批量全局替换（避免一次改坏全部界面且难以定位）。
3. **不删除旧语汇的代码路径**：被替换的样式若仍可能复用（如边框按钮），
   以注释形式保留在文件顶部（`// 旧档（framed）：...`），便于快速回填。

> 版本号是否滚动由用户决定（`docs/STATUS.md` §2）；本档改动并入当前版本，不自行发版。
